# Асинхронность в Python

Решение заданий 0–3 про загрузку 20 URL и разбор двух способов записи
`asyncio.gather`. В каждом файле задания есть объяснение в начальном docstring.
Для подготовки к защите открой [GUIDE.md](GUIDE.md), для вопроса про список —
[answers.md](answers.md).

Обе записи ниже выполняют запросы конкурентно:

```python
tasks = [fetch(client, url) for url in URLS]
await asyncio.gather(*tasks)

await asyncio.gather(*[fetch(client, url) for url in URLS])
```

Вторая запись не превращает запросы в последовательные и не создаёт ленивую
очередь. В CPython она позволяет раньше освободить контейнер списка ссылок.
Корутины, задачи и результаты всё равно требуют память пропорционально числу URL.

## Запуск

Нужен Python 3.12 или новее. Все команды выполняются из папки проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python main.py
```

В Windows окружение активируется командой `.venv\Scripts\activate`.
Если запускаешь через PyCharm, выбери интерпретатор `.venv/bin/python`
(Windows: `.venv\Scripts\python.exe`). Для обычного запуска без тестов
достаточно установить `requirements.txt`.

Отдельные примеры:

```bash
python task_0_fix_async.py
python task_1_sync_vs_async.py
python task_2_robust_fetch.py
python task_3_cpu_bound.py
python gather_nuance.py --count 100 10000 50000 --repeats 3
```

Первые четыре примера обращаются к реальным серверам. Эксперимент `gather_nuance`
и автоматические тесты работают без интернета. Повторный запуск `main.py`
обновляет `measurements/latest.json`.

## Проверки

```bash
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
python -m pip check
```

Тесты проверяют перекрытие запросов, сохранение порядка, последовательный цикл,
восстановление после 503, паузы 1 и 2 секунды, отсутствие ретраев для 404,
ограничение попыток при таймауте, внешнюю отмену и сохранение успешных результатов.

## Замеры

Фактический запуск 31 октября 2026, Python 3.12.14, macOS. Сетевые примеры
использовали 20 картинок 800×600; в задании 2 добавлены два битых адреса.

| Проверка | Результат |
| --- | --- |
| Задание 0, последовательный async | 6.489 с, 20 успешных ответов |
| Задание 0, gather со списком | 1.060 с, 20 успешных ответов |
| Задание 0, gather со списком внутри | 1.339 с, 20 успешных ответов |
| Задание 1, requests | 5.942 с, 20 успешных ответов |
| Задание 1, httpx async | 1.178 с, 20 успешных ответов |
| Задание 2, таймауты и ретраи | 12.025 с, 20 результатов и 2 ошибки |
| Задание 3, прямые вычисления | 2.619 с, пауза ticker 2.619 с |
| Задание 3, два процесса | 1.457 с, пауза ticker 0.101 с |

В задании 1 асинхронная версия оказалась быстрее примерно в 5.04 раза.
Это результат конкретного запуска, а не гарантия для любых серверов.
В задании 3 отдельно измерена загрузка: 1.915 с; CPU-сравнение использовало
одинаковые байты и дало одинаковые хеши.

Разница 1.060 и 1.339 с между двумя сетевыми `gather` не доказывает влияние
записи списка: внешние задержки и порядок запусков не контролировались.
Эксперимент ниже исключает сеть и меняет порядок вариантов между повторами.

Модель без сети, 50 000 корутин, медиана трёх повторов с `tracemalloc`:

| Вариант gather | Живых дочерних задач | Время | Память при ожидании | Локальный список |
| --- | ---: | ---: | ---: | ---: |
| Список в переменной | 50 000 | 0.656 с | 55.22 МиБ | 444 376 байт |
| Временный список внутри | 50 000 | 0.656 с | 54.79 МиБ | отсутствует |
| Генератор под `*` | 50 000 | 0.657 с | 54.79 МиБ | отсутствует |

Временный список освободился раньше, но число задач осталось тем же.
Это измерение памяти Python, а не полного потребления RAM процессом.
Накладные расходы `tracemalloc` включены во время.
Исходные числа сохранены в [measurements/latest.json](measurements/latest.json).
